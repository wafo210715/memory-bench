## A 段 · 形成期（query-independent）

| 阶段 | Paper | Code |
|---|---|---|
| A1 intake | 每来一条对话消息就触发一次，抽取时可带上最近几轮做上下文（§3.1.1；Figure A.1 写的是「从当前消息抽，必要时参考近邻上下文」） | 跑分时不碰原始对话，从磁盘上一份现成的事实文件里逐 session 逐轮读出事实字符串（`preextracted_pipeline.py:49`，由 `evaluate_locomo.py:744` 调）；该文件的元数据只有来源文件名和 session 数，既无模型版本也无生成脚本 |
| A2 distill | 抽取由一个专门微调的小模型一次调用完成四件事：滤掉低价值内容、把指代和相对时间消解成绝对表述、改写成第三人称、把图像描述当作一等信息源（Figure A.1 五条规则 txt:1189-1207）。随后一次调用解析人物、关键词、时间，并顺手标记这条事实是否暗示长期特征（§3.1.2；§3.3 txt:357-359）。事件侧一次调用决定归到哪些已有事件，可多选也可全不选（Algorithm 1 第 13 行 txt:1303），命中的每个事件各调一次重写摘要和关键词。画像侧在每个 session 结束时把攒下的候选批量抽成画像句（§3.3 txt:354-360） | 抽取那一步不执行（差异 1）。实际跑的是元数据解析一次调用，产出人物、关键词、时间和「要不要进画像队列」四个字段（`preextracted_pipeline.py:67`），关键词随后规范化并截到 5 个。事件归属同样一次调用，但用函数里的内联提示词，仓库那份 `event_attribution_prompt.txt` 加载了却从不被使用（`event_level_pipeline.py:166`，内联提示词 171-192）；命中的每个事件各调一次重写摘要（`event_manager.py:267-327`）。画像批处理由待处理条数攒够 10 条触发，计数跨 session 累积（`profile_manager.py:41`），触发后按人分组、每人各调一次 |
| A3 admit | 先用人物和时间元数据做符号过滤，明说是为了省下昂贵的向量计算（txt:233-235），再用混合相似度（向量余弦 α 加关键词 Jaccard β）取 top-k 得候选集 Cret（Eq.2）。然后一次调用同时产出两样东西：相对已有记忆真正新增的那部分内容，以及只在检测到逻辑冲突时才生成的更新元组（txt:264-274）。画像走同一套：检索同人 top-kp 已有画像，一次调用在冗余、更新当前值、改历史版本、新建之间四选一（txt:361-372） | 拆成三条互不复用的路径。去重不调 LLM，余弦超过 0.95 直接整条丢弃（`fact_storage.py:162`）。冲突检测先过人物兼容门（时间那一支是空操作，差异 9），混合相似度超过 0.6 取 top-5，一次调用只回答有没有冲突、是哪一条，命中就把旧记录的文本、向量、关键词、时间四个字段整条覆盖（`:79-82`）。事件归属另起一次全量相似检索取 top-10，用的是另一套权重（`fact_seeded_event_pipeline.py:132`）。画像检索同人 top-8，最高分低于 0.55 或文本规范化后完全相同就不调 LLM，否则一次调用四选一 |
| A4 index | 每条事实算一个稠密向量，它是事实结构里的一个字段（§3.1.2）。三类边的权重要用到当前查询的关键词，所以写入期不建持久图 | 同样每条事实算一个向量（all-MiniLM-L6-v2，384 维，`preextracted_pipeline.py:153`），与论文声明的统一 embedding 一致（txt:665）。没有近似最近邻索引，后续检索一律全量遍历打分 |
| A5 commit | 三个库：事实库写入新增内容并按更新元组改旧条目、事件库存成员与人物关键词时间和摘要、画像库存当前值加历史 | 三个 JSON 文件落盘，无数据库（`facts_/events_/profiles_<conv>.json`）。画像是全系统唯一保留旧版本的一层：改当前值前先把旧内容连同有效期克隆进历史（`temporal_profile_version_chain.py:131/410`），事实层则是直接覆盖 |
| A6 internalize | 把 Qwen3-14B 用 LoRA 微调成事实抽取器：4352 条样本、单卡 A100、学习率 5e-5、rank 128、有效批量 8、3 轮（Eq.1 txt:200-207；§4.1 txt:662-666） | |

| 阶段 | Paper | Code |

| B2 recall | 主召回按人物和时间过滤后用混合相似度取一半种子（ks/2 = 5，§A.6.1 txt:1537-1538）。补偿召回先在事件层排序取 top 事件，展开成员事实并排除主召回已拿到的。画像召回只在意图判定需要画像时进行，取 top-kp，查询带时间约束时挑该时刻有效的版本 | 三路结构一致：主召回 top-5（`retrieval.py:137`）、事件层 top-5 后展开（`:241`）、画像 top-5（`:57`）并按查询时间选当前值或某个历史版本（`incremental_temporal_profile.py:229`） |
| B3 expand | 以种子为起点做限跳扩展，邻居仍受人物和时间约束。关键词、事件、相邻轮次三类边的权重在查询时才算，因为关键词权重依赖当前查询（Eq.3-6）。种子分做幂变换后归一得到重启分布（Eq.9）；多通道游走按每个节点实际有出边的通道重新归一化通道权重（Eq.7-8） | 同样 2 跳、最多 180 个节点（`multichannel_graph.py:288`），三类边权同样查询时算。多两处论文没有的人物门控：关键词边在两侧人物都非空且不相交时归零，轮次边则要求人物通过、或共享关键词或事件（`:558-572`）。种子分先混入一点排名先验（0.05/(rank+1)）再做 5 次幂（`graph_rerank.py:83-114`） |

| B5 select | | 主召回与补偿召回合并去重后截到 10 条，作为图的种子（`run_atommem_pipeline.py:339`） |
| B6 deliver | 把召回的事实、画像，连同每条事实对应的事件摘要一起组装成上下文（两张 prompt 图的 Input 第四项 txt:1739/1762；正文 txt:436） | 事件摘要每次查询都算了，但在生成函数入口被丢弃，实际进 prompt 的只有查询、画像、事实三项（算在 `run_atommem_pipeline.py:399`，丢在 `query_response.py:195/198/234`）。模板按题目类别三选一，时间推理类走一份论文里没有的专用模板 |

## 重点差异详述

### 1. Fact Executor 整条抽取链在跑分链路不存在（A6/A2，能力损失）

论文把抽取器写成一号贡献：4352 条样本对 Qwen3-14B 做 LoRA 微调（Eq.1 txt:200-207；§4.1 txt:662-666），数据经 GPT-4o 教师加人工精修两阶段构造（§A.1.2-A.1.3），抽取规则由 Figure A.1 五条给定（txt:1189-1207）。仓库里既没有权重（`*.pt/*.ckpt/*.bin/*.safetensors/*.pth` 查找零结果），也没有训练或推理依赖（`requirements.txt` 无 torch/transformers/peft）。跑分入口直接读磁盘上的现成事实（`evaluate_locomo.py:744` → `preextracted_pipeline.py:49`），而那份 JSON 的元数据只有来源文件名和 session 数，无从追溯是谁、用什么模型抽的。后果是：论文 §4.2 那句「记忆存储质量至上，精巧的系统编排无法弥补有缺陷的记忆表示」（txt:828-831）所依赖的那一步，恰恰是这个仓库里唯一无法验证也无法复现的一步。

### 2. Fact Verification 的残差提炼不存在（A3，能力损失）

论文是一次调用同时产出两样东西：相对已有上下文真正新增的那部分内容，以及只在检测到逻辑冲突时才生成的更新元组，并称这个联合机制既防冗余又维护全局一致性（txt:264-274）。代码把它拆成两条独立路径：余弦超过 0.95 直接整条丢弃、全程不调 LLM（`fact_storage.py:162`，阈值 `config.py:59`）；否则一次调用只回答有没有冲突、是哪一条（`:246-247`），命中就把旧记录的文本、向量、关键词、时间四个字段整条覆盖并立刻落盘，新记录不入库（`:79-89`）。于是每条事实只有三种归宿——整条存、整条丢、整条覆盖，论文那种「只留下增量」的中间态在代码里没有对应物，被覆盖掉的旧文本和旧向量也不进任何历史列表（画像层是全系统唯一保留版本的地方，见清单 12 与 A5 一格）。

### 3. event_contexts 算了但在最终 prompt 前被丢弃（B6，能力损失）

论文有三处说事件摘要参与答案生成：两张 prompt 图的 Input 第四项（Figure 8/A.3 txt:1739；Figure 9/A.4 txt:1762）和正文的「由事件级上下文加以丰富」（txt:436）。代码每次查询都认真算了这个字典（`_build_event_contexts`, `run_atommem_pipeline.py:399`，把 fact_id 映射到事件摘要），也一路传到生成函数门口（`:365`→`:373`），随即在函数体里被丢掉：先是一行 `_ = event_contexts, query_info`（`query_response.py:195`），接着手动传空字典进格式化函数（`:198`），格式化函数内部再丢一次（`:234`）。三份答题模板的输入说明也只有查询、画像、事实三项，开放域那份第 12 行还明令不得使用事件摘要。结论是：事件层在代码里只影响召回（B2 的补偿召回、B3 的事件边），对最终 prompt 零贡献。

### 4. 时间推理类单开一套论文没有的答题模板（B6，纯加法）

论文 Figure 8 的 caption 明确说这一份 prompt 同时用于单跳、多跳和时间推理三类任务（txt:1753-1754）。代码却按 LoCoMo 的 category 三选一（`_load_category_prompt`, `query_response.py:46-58`）：cat2 走一份论文里完全不存在的时间推理模板，25 行，含五条时间表达规则和四条输出规则（例如把日期表述成「the Sunday before 22 May 2023」这类锚定式相对时间）；cat3 与 Figure 9 只是主题相同，五条推理规则、四条输出规则和两个范例全是自写。影响直接落在 Table 1 的 Temporal 三列上：论文报告的 62.78 / 57.64 / 66.98 是带专用模板跑出来的，照 Figure 8 复现拿不到同一条件。

### 5. Table 2 的消融变体在仓库里没有复现路径（全局，能力损失）

Table 2 给了三个变体的完整指标（txt:730-817），caption 说明 AtomMem-FLAT 去掉层级记忆结构、w/o Profile 去掉画像记忆、w/o Graph 去掉图关联召回（txt:823-825）。仓库的命令行参数里只有 `--disable-graph`（`run_atommem_pipeline.py:558`）对得上第三个；全仓库检索 flat、ablation、disable profile 只命中 `query_response.py:222` 的一句 "(No profiles found)" 字符串。而且 Flat 与完整版的 token 差（722.75K vs 21357.06K，Table 1）说明它不是纯检索侧改动，构建期也停掉了一部分——而仓库里没有任何能停掉画像构建或事件构建的开关。

### 6. README 的环境变量名与代码不一致，抽取器端点静默失效（A2，文档脱节）

README 的配置一节教用户设 `ATOMMEM_FACT_EXECUTOR_API_KEY` / `_API_BASE` / `_MODEL`，`config.py:49-51` 实际读的是 `ATOMMEM_FACT_EXTRACTOR_*`（EXECUTOR 与 EXTRACTOR 之差）。三个变量都写了回落默认值，分别落到通用的 `API_KEY`、`API_BASE`、`LLM_MODEL`，所以照 README 配置不会报错，只会静默地用通用模型（默认 gpt-4o-mini）去跑抽取。它只在用 `--extract-facts` 自己抽事实时才起作用——而那条路径本来就不在跑分链路上（清单 1）。两个缺陷叠加的结果是：论文的抽取器在这个仓库里既跑不到，也配不上。

## memory-bench 封装口径（2026-09-10）

本仓库的 atommem 臂在 `servers/atommem/`（`server.py` + `extractor.py` + `embedding.py`），
注册见 `servers.yaml`，公平性配置登记在 `docs/interface-spec.md` §7。
上游只读核实，未做任何修改。封装对上面差异清单的处理逐条如下；
完整的口径决策表、门禁状态与开跑前须知在同目录 `REPRO-NOTES.md`。

| 差异 | 封装侧怎么做 | 依据 |
|---|---|---|
| 1 Fact Executor 缺席 | 按论文补齐：提示词逐条对齐 Figure A.1 五条规则（不是仓库自带那份缺两条的），模型换成全 arm 统一的 glm-5.3 temp=0。抽取器权重无法复现，统一 backbone 是可比性的下限 | 用户 2026-09-10 定：论文理念优先于照抄代码 |
| 3 event_contexts 被丢弃 | 按论文补齐：事件摘要拼进对应 fact 的 envelope 文本 | 同上 |

| 8 画像触发时机 | 在上游“攒够 10 条即触发”之上追加一次 session 末 flush（一次 add_conversation 即一个 session），比上游更接近论文的“每 session 结束触发”，但不是替代关系 | 契约的 session 边界天然对齐论文 |

封装自身引入的偏离（不是上游的，必须与上面分开读）：

- embedding 从 all-MiniLM-L6-v2（384d）换成 embedding-3（2048d），与 mem0/graphiti/mandol/rag_baseline 同口径。
  代价是上游三个硬编码阈值（去重 0.95、冲突门 0.6、画像免 LLM 0.55）都在 384d 尺度上调过，
  换维后触发率会漂——`stats().threshold_probes` 逐次记录三者的评估数、触发数与 top-1 相似度分布。
- 会话时间必须翻成上游 `parse_session_datetime` 认得的串（`on 8 May, 2023`）。
  直接传 ISO 会静默落到 `datetime.now()`，把每条 fact 的 interaction_time 和每条 profile 的
  valid_from 写成跑批当天，连带破坏检索侧时间过滤与画像版本链。2026-09-10 对抗审查实证并修复。
- envelope 条数：profiles 与 facts 共享 top_k 预算（profiles ≤5 先占位，facts 取剩余），
  同 graphiti 三类混合塞在 top_k 之内的先例，不额外追加。

本口径下未被测到的能力：

- Figure A.1 规则 4（多模态整合）无输入。LoCoMo 原始数据有 blip_caption / img_url，
  但 harness 的 `loaders/locomo.py:98` 只交 {role, content, timestamp}，图像描述在 loader 层已丢弃。

> [!warning] 已知机制边界：检索侧 people 硬交集
> `src/retrieval.py:284-288` 的主召回过滤在 query 解析出具名人物时，会拒掉一切 `people`
> 不与之相交的 fact（包括 `people` 为空的），且没有任何回退。上游自身并不一致——
> 图通道过滤（`multichannel_graph.py:612-614`）和写入侧 `people_sets_compatible`
> （`fact_storage.py:15`）都放行空集，只有主召回是严格交集。
> 后果：一旦 B1 把 query 里的非人名实体误判成人名，召回直接归零且静默。
> 2026-09-10 量化：LoCoMo 全库分层采样 200 题，query 解析出的人名落在该 conv 说话人名单外的
> 占 1.0%（2/200，且两例都是对话中提到的第三方人物，实际归零率更低）；
> 分题型 multi-hop 2.4%、open-domain 2.8%、其余 0%。
> 这也是 smoke 契约测试步骤 2/7 在中文无具名样本上归零的原因。
> 裁决：不加兑底——论文明写主召回按人物过滤，加回退属于擅自改进论文设计；
> 但归零不得静默，retrieve 逐题上报 `PEOPLE_FILTER_EMPTY` 并在 `stats().threshold_probes`
> 累计，出分时可单独统计它吃掉了多少题。完整论证见 `REPRO-NOTES.md` §1。
> 需要注意的是上游自身并不一致：图通道过滤与写入侧 `people_sets_compatible` 都放行空集，
> 只有主召回是严格交集——这是一个现成的消融项候选。

## 附：推导

1. 时代差几乎为零改变了判词的分布。论文 v1（2026-06-18）与代码快照（2026-06-14）相隔 4 天，没有「论文旧、代码后来演进」的解释空间。所以清单里的「能力损失」不能读成「后来退化了」，而应读成：论文描述在提交当日就超出了公开仓库的实现——差异 1、3、5 尤其如此。
2. 因果链不是并列观察。抽取器缺席（清单 1）是三格的上游：长期特征标志只能挪到元数据那次调用里（清单 14）；五条抽取规则的落地不一致在跑分链路上没有后果，因为两条路径都不跑（清单 13）；Table 1 的 token 统计也因此不含抽取成本。同理，联合验证被拆开（清单 2）直接生出一组论文里不存在的构建侧阈值（清单 12）。清单里分行列，但依赖写在了「差异」列。
3. 检索侧其实高度对齐，差异集中在写入侧。Table 5 的检索参数逐项核对下来与代码一致：重启概率 0.34、最多 20 轮、容差 1e-6、种子锐化 5 次幂、三通道权重 0.45/0.40/0.15、事件大小惩罚指数 1.25、最大事件 60、2 跳、180 节点、轮次窗口 2、衰减温度 2.0、边权 epsilon 1e-8、事件边与轮次边的扩展跳数 2 与 1，连关键词权重的六个惩罚系数都对得上。唯一的例外是每通道邻居上限（清单 11）。这也解释了为什么种子数拆成三个参数（清单 15）值得记一笔：整个检索侧只有它和邻居上限两处需要读代码才能对上论文。
