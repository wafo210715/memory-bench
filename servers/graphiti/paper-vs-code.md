# Zep / Graphiti 论文、上游代码与本仓库接入对照

> [!note] 口径
> 论文描述的是 Zep 服务中的记忆机制；上游代码是后来公开的 Graphiti 引擎。两者相隔约十九个半月，差异不等于论文失实（论文：2025-01-20，arXiv:2501.13956v1；上游：2026-09-03，0.30.1，提交 `a6e026f8fca27af9c1fc4cfe359c3834dc9655bb`）。
> 第三列只写本仓库接入脚本和已核实日志，不推断旧依赖库的内部实现。接入脚本版本为 `e60e189`；2026-09-06 核实的安装版本是 0.29.3，不能把上游 0.30.1 的内部行为直接搬过来。
> 事实优先取自 [[verification]]，下文简称 V；其中的 P/C/W/D 是核验编号。阶段归属参考两份 Graphiti flowgen spec。上一轮补核过的原文、接入代码和运行记录继续使用；两份 architecture 文档仅作为待纠正对象，不作事实源。
> 文中「实体」是对话中的人物、地点或具体对象；「事实」是关于它们的陈述；「社区」是一组联系紧密的实体及其综合摘要，不是现实社区或聊天群。
> 空白表示没有单独定义或实现这一步；没有核验的部分会明确说明，不拿空白代替。「默认死」表示代码存在，但被明确的默认开关关闭，不等于损坏或缺少凭证。
> 引文中的 `txt` 指 Rasmussen-2025-Zep-Temporal-Knowledge-Graph-Architecture-for-Agent-Memory.txt；上游短文件名均位于固定快照的 graphiti_core 内；`server.py` 只指本仓库接入脚本。

## A 段 · 形成期（query-independent）

| 阶段 | Paper | 上游 Code | memory-bench 臂 |
|---|---|---|---|
| A1 intake | 系统一次接收一条消息，同时保留说话人和消息发生时间。它也支持其它资料类型，但论文实验只使用消息（另支持 text/json；txt:102–109）。 | 调用方交入一段原始内容及其时间；引擎不要求这段内容必须是一条消息（`add_episode`；`graphiti.py:980–992,1098–1110`）。 | 接入脚本把一次完整会话拼成一段内容交入。它取第一条提供了时间的消息作为时间锚，缺失或解析失败时使用当前时间（`server.py:325–331,414–427`）。 |
| A2 distill | 模型先抽出人物和对象，再检查实体抽取有无遗漏或错误；此外还会提取事实、补上时间并生成摘要。关系紧密的实体会被归成社区，另作综合摘要（抽取参照最近四条消息；txt:130–136,148–194）。 | 模型负责抽实体、抽事实和补时间，但抽完实体后不再独立自检。已有摘要添入新事实后仍够短时，就直接保留；需要生成或压缩摘要时，才成批请模型处理。社区摘要的自动更新默认关闭（长摘要每批最多 30 个；`node_operations.py:63,244–252,836–913`；`graphiti.py:989,1184`）。 | 接入脚本把整段会话交给所装依赖库处理，不另做一次内容提炼。已有日志确认模型实际参与了写入，但不能用这些计数还原库内每一步（六个短样本各记录三次模型调用；`server.py:421–438`；V:C28）。 |
| A3 admit | 新信息入库前，系统先找相似的旧实体，再由模型判断是不是同一对象，并更新名称和摘要。重复事实只在同一对实体间比较；遇到矛盾时保留旧内容，但标明它何时不再有效（txt:137–170）。 | 系统先找相似的旧实体，能用规则确认是同一对象的直接合并，拿不准的再一起交给模型。模型同时找重复事实与矛盾事实，程序随后比较事实发生时间、决定哪条失效；刚收到的事实也可能已经过时（`node_operations.py:627–689`；`edge_operations.py:726–732,826–842`）。 | 重复和冲突判断都交给所装依赖库，接入脚本本身不再做一遍；本轮不推断旧库是否采用上游列中的批处理方法（`server.py:421–427`）。 |
| A4 index | 系统把实体名称、事实和社区名称转成向量，让它们以后能按语义被找到（实体名称使用 1024 维向量；txt:137,150–155,191–194；V:§3.1）。 | 系统为实体和事实计算向量；社区名称的向量随社区构建或更新一起生成，不会脱离社区内容单独出现（`node_operations.py:778`；`edge_operations.py:530–533`；`graphiti.py:1510–1513`）。 | 接入脚本指定编码模型和向量长度，日志确认写入时调用过编码服务。具体哪些对象各编码几次，没有在旧库内部重核（默认 embedding-3、2048 维；六个短样本各有八次或十二次编码调用；`server.py:247–252`；V:C28）。 |
| A5 commit | 原始消息、抽出的实体与事实、社区摘要分别保存在图中。写入使用预先定义的数据库语句，旧事实被标记失效后仍保留（Neo4j、预定义 Cypher；边上四个时间戳；txt:78–88,142–144,162–170）。 | 同样把这些内容保存到图中，并额外保存事实来源片段的参考时间。整个社区层需要调用专门的构建入口才会生成（`reference_time`；`graphiti.py:1170,1490–1524`；`edges.py:345–355`）。 | 内容保存在图数据库里，接入脚本另记下已写入哪些会话。它提供独立的社区构建工具，历史记录确认可以建出社区；正式三次重复实验中也有社区数据（Neo4j、scopes.json；`server.py:48,299–305,539–562`；181 个社区节点，`runs/locomo-r2-n3/system_stats.jsonl:2`）。 |
| A6 internalize | | | |

> [!tip] 为什么 A6 都空
> 三方描述的都是保存和使用外部记忆，不是把这些记忆训练进模型参数。数据库初始化时创建的静态索引也不单算 A4；A4 记录的是对记忆内容逐项进行的编码。

## B 段 · 动员期（query-conditioned）

| 阶段 | Paper | 上游 Code | memory-bench 臂 |
|---|---|---|---|
| B1 cue | | 系统清理问题中的换行，再把问题编码成向量；不另做意图分析或时间范围解析（`search/search.py:117–149`）。 | 接入脚本原样传入问题，日志显示每次检索会把问题编码一次（早期试跑共 105 次；`server.py:477,531`；`runs/graphiti-align-shakeout/mcp_trace/graphiti.jsonl:3–107`）。 |
| B2 recall | 系统同时按用词是否匹配、含义是否接近来找记忆。搜索对象是事实、实体名称和社区名称（词面检索用 BM25，语义检索用余弦相似度；txt:229–241）。 | 高级入口查事实、实体、社区和原始片段；前三类结合词面与语义，原始片段只查词面。各类分别限制返回数量，并允许附加过滤条件；另一个简单入口只查事实（高级入口 `search_()`；默认每类最多 10 条，不是合计 10 条；`search_config_recipes.py:81–116`；`search_config.py:29,117`）。 | 接入脚本只查事实、实体和社区，不取原始片段；可以限定查哪段对话，但不转交更细的时间或类型条件。它先给每类留出候选，再由后续步骤控制总数量（关闭原文通道：`episode_config=None`；每类上限默认 `max(top_k,20)`，相似度阈值 0.6；`server.py:64–114,458–477`）。 |
| B3 expand | 找记忆时，系统还可以沿图中的关系向外找相邻内容，并以最近的原始片段作为入口；论文没有固定向外走多少层（广度优先搜索 BFS；txt:244–248）。 | 如果启用了关系扩展，却没有指定起点，系统会先检索一轮，再从这轮找到的实体继续沿关系查一次。扩展深度有默认上限，社区不走这条路径（默认三层；`search/search.py:332–353,541–560`；`search_utils.py:67`）。 | 接入脚本没有另外指定起点，因此让库自行扩展。早期日志看到过先无结果、后有结果的两次扩展，但不能把一次的命中数当作普遍规律（深度默认三层；首条检索两次各命中 0、40 条；`server.py:66,133,477`；上述试跑日志:3）。 |
| B4 appraise | 系统可以综合每条记忆在多路检索中的名次，得到一个总排名；换用其它排序方法时，则分别倾向于把相关但彼此较少重复、被提及更多、离指定实体更近，或被模型判断更相关的记忆排在前面（RRF、MMR、episode-mentions、node-distance、cross-encoder；txt:254–264）。 | 高级入口默认使用重排模型；其它可选方法按记忆类型有所不同。简单入口默认合并排名，指定中心实体时则改按距离排序（事实/实体各五种、社区三种、原始片段两种；`search_config.py:53–77`；`graphiti.py:1569–1571,1606`）。 | 本臂默认只合并多路排名，不再请模型打相关性分数。虽然可以切到模型重排，但这个兼容分支只能给出“相关”和“不相关”两档分数（默认 RRF；可选分支将 True/False 转为 1/0；`server.py:65,94–100,146–208`；V:W6/W7）。 |
| B5 select | | | 总返回数量有限时，接入脚本先按比例为事实、实体和社区分配名额。若某类凑不满，就按事实、实体、社区的顺序，从各类尚未入选的候选中补充结果，直到填满空位或候选用尽（比例 3:1:1，以最大余额法取整；`server.py:387–409,487–490`）。 |
| B6 deliver | 系统把找到的记忆整理成供答题模型阅读的上下文：事实附有效日期，实体附名称和摘要，社区附综合摘要（论文称这一步为 χ；txt:208–226）。 | 检索接口先返回结构化结果；调用方还可以用现成的辅助函数把结果转成文本。把记忆拼成上下文的功能确实存在，只是检索接口不会自动替调用方执行（`search_results_to_context_string`；`graphiti.py:1612–1629`；`search_helpers.py:27–72`）。 | 接入脚本自己生成统一的证据条目，并把事实有效日期写进时间栏。缺少事实时间时就标为未知，不用入库时间冒充；交付的条目不带原生评分或逐条会话出处（统一条目称 envelope；`server.py:346–385`）。 |
| B7 generate | 回答问题由记忆系统之外的模型负责；它读取整理好的上下文后生成答案（实验使用 gpt-4o-mini、gpt-4o，DMR 另用 gpt-4-turbo；txt:197–200,284–288）。 | 记忆库返回搜索结果后就结束，答案由调用方的模型生成（`graphiti.py:1612–1629`）。 | 评测脚本把选中的证据交给答题模型，本臂本身不负责回答（本文引用的实验使用 glm-5.3；`runs/locomo-r2-n3/manifest.json:24–27`）。 |
| B8 loop | | | |

> [!tip] 其余空格怎么理解
> 论文没有单独描述查询准备，所以 B1 留空；这不等于证明论文实际不编码查询，只能确认两边披露的步骤不同，不把它列为能力新增或文档错误。论文和上游只是截取排序靠前的结果，没有本臂这种跨类型名额分配，所以 B5 留空。
> 三方都没有根据本轮效果判断“继续查还是停止”的检索回环。代码中固定补查一次相邻内容属于 B3，不是 B8；算法内部反复计算也不自动算 B8（V:§3.2/§4.2；`search/search.py:332–353,461`）。

## 差异清单

清单按具体比较对象逐项列出，不把接入脚本的限制算到整个上游引擎上。重要度只看能力边界、机制和实现细节；同一原因的后果写明依赖关系。核验报告中的一致项 D20 不冒充差异，但本臂改用不同向量长度另列为第 16 项。

| # | 阶段 | 差异 | 类型 | 重要度 |
|---|---|---|---|---|
| 01 | A1 | 论文一次处理一条消息，本臂一次交入整段会话，因此记忆提炼的输入粒度变了（V:D17；`server.py:414–427`）。 | 设计演进 | 中 |
| 02 | A1/A2 | 论文抽取时参考最近四条消息，上游快照默认参考最近十个原始片段；这不等于已核实旧运行包使用十个会话（V:C12/D17；`search_utils.py:64`；`graphiti.py:1087–1095`）。 | 设计演进 | 中 |

## 重点差异详述

按本次确认，只展开以下五项。其它高重要度条目仍完整保留在清单中；中、低项不另写长段落。

### 04 · 抽取后没有独立复检（能力损失）
论文要求先抽取对话中的人物和对象，再回看结果，减少漏抽和误抽；这次“回头检查”本身就是一个独立步骤（txt:133–134）。
当前上游只做一次实体抽取，随后就继续处理结果，没有再让模型检查一次（`node_operations.py:244–252`）。
它确实增加了更严格的抽取要求，但“事先约束怎么抽”和“抽完后再查错”不是同一件事，不能直接认定效果等价（`prompts/extract_nodes.py:90–114`）。
这说明当前路径少了一种自检机制，不说明十九个多月前的论文失实；本轮也不据此推断旧运行包内部如何工作。

### 21 · 上游可以直接找回原文，本臂不接这条路（纯加法）
论文会保存原始对话，但检索结果只定义了从中提取的事实、实体与社区，没有单列原文搜索通道（txt:120–125,202–205）。
上游增加了按词语直接搜索原始片段的路径，也能把搜到的原文交给后续模型；这是可检索内容范围的扩展（`search_config_recipes.py:98–103`；`search_helpers.py:40–45`）。
本仓库为了保持三类结果，明确关闭了原文通道，所以“上游能直接找原文”不能套用到本臂（`server.py:74–75,114`）。
清单第 21 项记上游的新增能力，第 22 项记接入时不开放该能力；两项相关，但不是同一个主体的同一种变化。

### 25 · 能记录时间，不等于已经按时间筛选（纯加法）
论文没有规定每次搜索应只找当前事实，还是允许查历史事实；上游则提供接口，让调用方按时间、实体标签或事实类型缩小候选范围（V:P47/C48；`search_filters.py:55–67`）。
调用方需要明确给出筛选条件。没有设置时间条件时，已失效的历史事实也可能返回，因此不能把默认检索结果理解为只包含当前仍成立的事实（`graphiti.py:1625`）。
本臂目前只转交对话范围，其它筛选条件会被忽略并告警；事实的有效日期仍会写进交付文本，但那不是库内筛选（`server.py:356–368,458–477`）。
因此必须分别判断“有没有时间信息”和“有没有用时间限制候选”，不能从前者推出后者，也不能无条件认定历史事实都该被删掉。

### 14 · 社区划分可能一直重算，和默认关闭不是一回事（能力损失）
社区构建需要反复调整实体分组，直到分组不再变化；当前上游每轮同时更新全部标签，而且没有迭代次数上限（`community_operations.py:100–131`；`driver/operations/graph_utils.py:27–59`）。
两个相连节点就可能不断交换分组标签：这一轮互换，下一轮又换回来，程序始终认为“还在变化”（反例中两边邻居权重各为 2，标签在 `(0,1)` 与 `(1,0)` 间交替）。
这时构建可能不结束，所以需要终止保障；本仓库保存过旧版本不收敛的实测记录和修补代码，但本轮不进一步推断旧驱动的内部路径（V:C43；`patches/graphiti/community_operations.py:100–125`）。
默认不自动建社区只是触发方式；某次试跑没有社区也只是运行状态。正式三次重复实验里已有社区，不能将这些情况都写成“社区功能不存在”（181 个节点；`runs/locomo-r2-n3/system_stats.jsonl:2`）。

### 32 · 模型重排只能判断两档，不能细分相关程度（能力损失）
上游重排客户端可以给出连续的相关性分数，用来区分几条“都相关”的记忆谁更相关；本臂的兼容分支只接受“相关/不相关”两类输出（V:W7；`server.py:146–176`）。
因此，多条被判断为相关的结果会得到相同分数，彼此先后主要沿用此前顺序，不能把这种二值结果称作连续分数的等价实现（True/False 转为 1/0，并稳定排序；`server.py:176,207`）。
若要复现论文所用的模型重排，就需要恢复相应的打分能力，或者明确承认使用了降级方法，而不是只沿用同一个功能名字。
但本仓库本文所引的正式实验默认只合并排名，没有运行这条模型重排分支，所以不能拿它的局限直接解释这次低分（默认 RRF；`server.py:65`；`runs/locomo-r2-n3/mcp_trace/graphiti.jsonl:1`）。

## Benchmark

### 2024–2025 · 论文实验

论文实验在 2024 年 12 月至 2025 年 1 月进行，测的是 Zep 服务，不是后来的开源快照。建图使用较小的语言模型，向量编码与重排使用另一组模型（建图 gpt-4o-mini-2024-07-18；原文称编码和重排均为 BAAI BGE-m3；txt:284–288,349）。

DMR 从多会话聊天数据中取出若干段对话，每段设置一个问答对，主要检查能否找回单个事实。分数由模型将回答与标准答案比较后判定（500 个 conversation；MSC 子集；LLM judge accuracy；txt:267–269,313–329）。

| 任务与题型 | 答题模型 | 指标 | Zep | 同模型基线 | 证据 |
|---|---|---|---|---|---|
| DMR：单轮事实检索 | gpt-4-turbo-2024-04-09 | 准确率 | 94.8% | 直接提供全部对话：94.4%；提供会话摘要：78.6% | Table 1，txt:300–304 |
| DMR：单轮事实检索 | gpt-4o-mini-2024-07-18 | 准确率 | 98.2% | 直接提供全部对话：98.0%；提供会话摘要：88.0% | Table 1，txt:305–307 |

只和同模型的完整对话基线比较，提升很小，不能写成大幅领先（分别高 0.4、0.2 个百分点）。论文转引的 MemGPT 旧成绩不混入本轮基线；换成较小答题模型时，作者也未成功复现 MemGPT（txt:308–309,321–326）。

LongMemEval_S 检查更长对话中的记忆使用。题型包括单次会话中的用户信息、助手信息、偏好，以及跨会话推理、知识更新、时间推理；判分使用按题型设计的提示词（平均历史约 115k tokens；GPT-4o judge；txt:341–359）。

| 任务 | 答题模型 | 指标 | Zep | 同模型完整上下文基线 | 证据 |

| LongMemEval_S | gpt-4o-mini-2024-07-18 | 准确率 | 63.8% | 55.4% | Table 2，txt:378–380 |
