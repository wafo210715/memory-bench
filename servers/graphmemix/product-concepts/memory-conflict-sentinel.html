记忆冲突哨兵 Memory Conflict Sentinel

常驻在 agent 侧边的哨兵面板，主动把系统在回答问题过程中顺带发现的「记忆之间互相矛盾/重复」摆到用户面前，而不是等用户自己撞见前后不一致的回答。

为什么这个形态配这个系统

对应机制画像的哪一步：关系验证 ECV 那一步——判断候选相对锚点是「新事实 / 澄清 / 佐证 / 冗余 / 冲突 / 无关」六选一。本产品只取其中「冗余」与「冲突」两种角色，把它们从内部过滤逻辑升级成用户可见的提醒。

为什么换个记忆系统做不出来：纯相似度检索系统只会把两条矛盾的记忆分别单独召回，最多因为向量接近而挤在结果列表里，但从不会显式判断"这两条是不是在打架"——冲突判定需要模型在锚点条件下逐边验证，这是 GraphMemix 特有的边级验证原语（ECV）。没有这一步，产品连"冲突"这个概念都构造不出来，只能做"相似记忆聚类"这种弱得多的功能。
