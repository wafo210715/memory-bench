# MemHarness Paper ↔ Code ↔ 本仓库臂 对照

> [!note] 口径
> paper = Wu, R. et al. "MemHarness: Memory Is Reconstructed, Not Replayed." arXiv:2607.28272v1（提交于 2026-07-30）。
> 上游代码 = KnowledgeXLab/MemHarness @ `31329e8`（2026-08-07 "add cold start data"），与论文提交相隔仅一周，属零时代差，不默认"差异=演进"，判断方式沿用同目录 `verification.md` 的逐条复核方法与判定符号（`✓`/`✗`/`◐`/`?`）；与 `paper-architecture.md`、`code-architecture.md` 表述冲突处，一律以 `verification.md` 的逐条证据为准。
> 本仓库臂 = `memory-bench` 的 `servers/memharness/server.py`（2026-09-12 新写），已注册进仓库根 `servers.yaml`，与上游/论文相隔约一个月，属主动设计决策，不是自然演进。
>
> 为什么是三列：本系统已经被本仓库复现成一条可跑的 MCP 臂（`server.py` 存在且已注册），按判据这属于"本仓库自己复现过"的一类，在论文与上游代码之外还有第三个真实来源需要对照——本仓库臂的实测行为。
>
> 第三列的边界：本仓库只复现记忆系统本体——蒸馏、去重、向量化、持久化、召回、批判重构这一整条链路；不复现 GRPO 训练层（第三列的 A6 永远空白，本臂不做任何梯度更新，也没有可训练的策略权重）、不复现冷启动 SFT（同样是 A6 空白的一部分）、不复现论文里"策略自己决定何时检索"的 agentic 触发（LoCoMo 静态 forced-call 下由评测循环逐次给出 query，B1 每次上报 `AGENTIC_TRIGGER_BYPASSED` 作为口径声明）。任务域也从原本的 ALFWorld/WebShop 具身与购物 agent 环境迁移到了 LoCoMo 静态多会话问答，因此蒸馏的粒度从一次 RL episode 轨迹变成一段对话 session。
>
> 空格 = 该阶段在这一列不存在。默认死 = 代码/配置完整但被显式关闭或从未触发，非损坏、非缺凭证；每条都要能指到具体关掉它的那行代码或配置。

## A 段 · 形成期（query-independent）

| 阶段 | Paper | 上游代码 | 本仓库臂 |
|---|---|---|---|
| A1 intake | 训练态下每次 GRPO 批量 rollout 完成后，所有轨迹一起进入待蒸馏候选池，先按保留比例做筛选，优先让成功与失败轨迹配额均衡，配额不够时随机从剩余轨迹里补齐（Appendix A.3，保留 50%） | 同论文一致，但多一道门：只有训练态（`is_train=True`）的 rollout 批次会走这一步，验证/测试轨迹从不进入候选池，避免评测数据泄漏进训练用的记忆库；保留比例由 `grpo_summarize_keep_fraction` 给出，基础默认与脚本实际取值都是 0.5 | 没有训练/评测的区分，也没有保留比例这个概念：每次 `add_conversation` 调用传入的一整段会话就是唯一的候选单位，一次性全部进入下一步蒸馏，不做抽样；蒸馏粒度也从一次 RL episode 变成一段 LoCoMo 对话 session |
| A2 distill | 由同一个正在训练的策略 πθ 自己做蒸馏，把轨迹压缩成 situation 与 memory 两段文本；prompt 见 Appendix Figure 9，一次调用最多产出若干条记忆（附录模板留了数量占位符，具体数值论文正文未给出） | 蒸馏器可配置：基础默认是完全不蒸馏，两个训练脚本都覆盖成复用同一份 actor rollout 权重批量生成 JSON（也支持走一个独立的 OpenAI 兼容 HTTP 接口）；JSON 解析失败按最多 3 次重试同一条轨迹；每条轨迹默认只产出 1 条记忆 | 蒸馏器固定是一个独立配置的 LLM（温度 0），不存在可复用的策略权重这个概念；prompt 保留了上游 compact schema 的 JSON 形状与 situation/memory 二元结构，但把域描述从 agent 轨迹换成对话会话（默认对话风格，上游原版的 agent 轨迹风格提示词保留作可切换对照）；每段会话默认产出至多 8 条记忆，明显宽于上游默认的 1 条 |
| A3 admit | 写入前做一次最近邻探测：新条目与库内已有条目的最大余弦相似度超过阈值（默认 0.85）就跳过写入；论文明确说这项策略 ALFWorld 关、WebShop 开，两个 benchmark 不用同一套 | 同一套阈值机制，比较符用大于等于而非论文写的严格大于（量级影响可忽略）；两个训练脚本里 ALFWorld 那份确实显式关闭这一项，WebShop 那份未覆盖、维持默认开启，与论文描述一致 | 同样的最近邻探测逻辑，统一开启且阈值维持 0.85（单一 LoCoMo 域，不需要区分两套 benchmark 策略）；比较池比上游多算了一点：本轮同一次调用里已经被接受的条目也会立刻纳入去重比较池，避免同一段会话内部的重复记忆漏网 |
| A4 index | 统一用 BGE-M3 给库内条目和查询向量编码 | 编码由一个远端 OpenAI 兼容接口提供（默认模型 bge_m3、1024 维），本地进程不跑 embedding 模型本身，接口地址未配置时直接报错 | 同样走远端接口，但模型换成 embedding-3（2048 维），与仓库内其他臂保持同一口径；维度更换让两条 0.85 去重阈值的尺度发生漂移，用统计接口逐次记录触发率作为观测手段，不改判定逻辑本身 |
| A5 commit | 记忆库是一组（策略、来源观察）二元组，用 Milvus 向量数据库承载 | 本地单文件 Milvus-Lite 承载，一条记录有 19 个标量/向量字段（还包含动作文本、奖励、是否成功、检索次数、效用值等 RL 训练相关字段），向量字段用穷举式索引配余弦度量 | 落盘成两个文件：一份存约 9 个字段（记忆 id、会话 id、scope id、情境、原则、时间戳、三个效用计数/分数字段），原则文本的向量另存一份；检索后端是 numpy 暴力余弦，在数学上等价于上游 Milvus-Lite 的穷举式索引，省掉了引入 Milvus 依赖和上游文档记录的多进程写入竞态未验证问题 |
| A6 internalize | 分两段：RL 训练之前先有一次离线冷启动 SFT，用 GPT-5.1 造种子数据，对协议格式做微调对齐；真正的批判与重构能力论文自己说是后续 GRPO 端到端学出来的（隐变量，无标注，只靠 episode 级奖励） | 两段都有对应脚本，参数与论文一致；但 GRPO 训练本该把重构这次生成的 completion token 和动作生成 token 一起计入轨迹级优势分配，在论文实际使用的配置下，训练开关函数直接返回否，重构那次生成完全不进任何梯度更新——即代码里"internalize"这一步实际只塑造了动作生成能力，没有塑造论文声称的重构能力（详见重点差异） | |

> [!tip] A6 只有论文和上游代码亮着，本仓库臂全空
> 本臂不做任何训练：没有 SFT、没有 GRPO，也没有可更新的策略权重。蒸馏与重构用的都是同一个外部配置好的现成模型，行为完全由 prompt 和采样参数决定，不存在"能力是学出来的"这个环节。

## B 段 · 动员期（query-conditioned）

| 阶段 | Paper | 上游代码 | 本仓库臂 |
|---|---|---|---|
| B1 cue | 正文把触发描述成策略自己根据当前历史窗口决定要不要查；但附录另一处又说是"每一步都检索"，论文没有协调这两种互相矛盾的描述 | 基础默认是无条件每步都检索（与附录的描述吻合），但两个训练脚本都显式覆盖成模型自己决定（与正文吻合）——论文实验实际跑的是正文那一种；查询文本从模型输出里的标签正则抽出，这一步不算一次环境动作但仍计入 episode 的步数预算 | 两种触发方式都不需要：由评测循环在每次 forced-call 里直接把 query 文本传给检索工具，不存在"要不要查"这个决策点，每次调用都在返回值里声明这一步是被接管的 |
| B2 recall | 用一个"由上下文推导出的查询"去检索，返回若干条最相关结果，按余弦相似度排序 | 检索键固定用记忆文本字段（论文没有明确说索引建在原则文本还是来源观察上），返回宽度基础默认与论文一致，命中项按最低分过滤，不限定只查成功过的轨迹 | 同样用原则文本的向量做余弦检索；返回宽度由调用方传入而非硬编码，最低分过滤维持不变；没有成功/失败这个维度，也就没有"只查成功轨迹"这个开关 |
| B3 expand | 附录把这一步写成无条件的固定流程：先取一个更大的候选池，再做一次贪心去重，最后截断到目标宽度 | 同样的先扩后收结构，阈值默认 0.85；但 ALFWorld 那份训练脚本也把这一项关掉了，WebShop 未覆盖维持默认——即论文写成"无条件"的这一步，在 ALFWorld 上实际是关的，论文只区分了写入去重的 benchmark 差异，没提检索去重也分 | 同样的先扩后收结构，统一开启阈值 0.85（单一 LoCoMo 域不需要区分两套 benchmark 配置） |
| B4 appraise | 检索到的若干条（经验，来源状态）对不会直接进下一步 prompt，而是先整体拼进一个重构上下文，同一个策略对它采样一次得到 guidance，若判定不适用则输出空标记、回退到自主推理指令；论文把"批判"和"重构"合并成这一步内部完成的单次输出，没有独立的批判产物字段——可观测到的只是这个输出是否为空这一个二元结果，论文的拒绝率与接受/拒绝曲线都是从这个二元结果反推统计出来的 | 检索宽度默认为若干条，但只有最相关的一条会被送去做批判重写，其余命中直接原样通过；这次重写是一次独立的批量生成调用（不是一次前向内部的多阶段输出），复用哪份权重可配置，论文实验里设成复用主策略；即使检索零命中，系统仍会注入一句兜底提示语当作"已检索到的内容"，使这一步照样跑一遍（不要求真的取回记忆内容） | 重构调用与上游用逐字一致的 system/user prompt 模板，但重构宽度默认改成对全部命中都做重构，而不是上游默认的只重构第一条（可用环境变量退回上游默认）——理由是 LoCoMo 评测下各臂统一用较宽的返回宽度，只重构第一条会让剩下的证据全部绕过论文这个头号机制；判定拒绝的逻辑（空标记、误吐协议标签当作拒绝、调用失败按拒绝处理）与上游逐条对齐；由于本臂不训练，重构用的是全局固定温度 0 的现成模型而不是被训练塑造过的策略——在中文语料上实测这一步的语言输出不稳定（连续 3 次蒸馏里 2 次中文 1 次英文），论文与上游是靠格式奖励与一条专门的英文塑形奖励把输出锁定成英文的，本臂完全没有这两层训练约束 |
| B5 select | | | |
| B6 deliver | 把重构后的 guidance（或回退到的自主推理指令）连同任务描述、历史窗口一起交给下一次动作生成采样 | 把重构后的 guidance 原地替换进观察文本里记忆标签块的内容，如果判定不适用就整块删掉、换成兜底提示语；这个替换发生在下一次真正的动作生成调用之前 | 不做任何文本拼接或替换：检索工具把每条结果包装成结构化返回值，用一个字段区分这条文本是经过重构的还是原样未重构通过的，至于怎么把这些结果拼进下游 prompt 由调用方（评测循环）决定 |
| B7 generate | 论文自己把这一步划在记忆系统边界之外，但物理上两次采样共用同一个策略 | 同一份策略权重做下一次生成调用，产出真正的环境动作；论文的"边界外"只是概念划分，代码里它和记忆系统的其它调用运行在同一个模型实例上 | |
| B8 loop | | | |

> [!tip] B5/B8 三方都空，B7 只有本仓库臂空
> B5 空的成因一致：批判重构那一步的接受/拒绝已经是二元结果，被拒绝的条目直接消失、被接受的条目全部进入下一步，三方都没有再单独做一次"合并再截断"的选择动作。B8 空的成因也一致：单次检索决策点内没有任何一方支持"再来一轮"的递归重查，是否再检索要等下一个观察步骤重新触发 B1。
> B7 只有本仓库臂空——六工具契约里没有生成答案这个工具，QA 答案由评测循环自己调用 LLM 完成，物理上与 memharness 进程完全分离；论文与上游虽然把这一步划在概念边界之外，但物理上仍由同一个策略模型完成。

## 重点差异详述

### 11. 重构 token 的信用分配在论文实际配置下不成立（A6，能力损失）

论文正文明确写轨迹级优势要同等分配给思考、重构、动作生成这三类 token，并称重构与动作生成"共享参数、联合优化"。但代码里判断是否需要单独训练重构模块的那个函数，在论文两个训练脚本实际使用的配置（重构调用复用主策略权重）下会直接返回否，导致后续的训练缓冲区始终为空，训练循环里整段针对重构模块的梯度更新逻辑被跳过。结果是：重构这次生成产出的 completion token，在论文自己的实验配置下完全没有进入任何一次梯度更新——论文关于"联合优化"的表述，描述的是一个在其实际实验里从未发生过的训练动态。

### 15. 检索触发方式三方各不相同，且论文自身内部已有矛盾（B1，设计演进）

论文正文把触发描述成策略自己根据当前状态决定要不要查（agentic），但附录另一处又说是无条件的每一步都查（fixed），两处描述互相矛盾，论文没有协调。上游代码把两种模式都实现了，基础默认是 fixed，但两个训练脚本都显式覆盖成 agentic——即论文实验实际跑的是正文那一种，附录的表述与实际实验配置不符。本仓库臂两种都不用：LoCoMo 静态 forced-call 场景下，检索的时机与内容完全由评测循环给定，检索工具本身不做任何"要不要查"的判断，每次调用都在返回值里声明这一步是被接管的。三层各自代表了"策略自主决定""基础配置的无条件检索""外部完全接管"三种不同的控制权归属，这条链路直接决定了记忆系统在整体架构里到底由谁掌握主动权。

### 21. 重构覆盖宽度三方不同，决定论文头号机制实际生效的比例（B4，设计演进）

论文正文的重构上下文公式把全部检索到的证据（若干条经验与来源状态对）一起拼进重构 prompt 做批判重写，暗示所有命中都会经过这一步。但代码里检索返回若干条命中之后，只有最相关的第一条会被送去做批判重写，其余命中原样通过——即便检索宽度设得再大，能真正经过论文头号机制"批判并重构"的也只有其中一条，这与论文正文的公式描述不一致（论文附录里的重构 prompt 模板本身也只留了单个证据的占位符，代码站在附录这一侧）。本仓库臂选择把默认行为改成对全部命中都做重构：由于 LoCoMo 评测下各臂统一使用较宽的检索宽度，如果沿用上游默认只重构一条，剩下的证据会在评测里完全绕过论文这个头号机制，等于没有真正测到它。这个参数可以用环境变量退回上游默认值。

### 25. 本仓库臂完全不训练，是与论文/上游最根本的结构性差异（全局，能力损失）

论文的核心叙事是策略通过强化学习隐式学会"什么时候该查、查到的东西该怎么改写"这套能力，训练分两段——协议格式的冷启动 SFT，以及之后端到端优化任务成功率的 GRPO；上游代码为这两段各自准备了完整的训练脚本与配置。本仓库臂里两段训练都不存在：没有 SFT 权重、没有 GRPO 循环、也没有任何一次梯度更新，蒸馏与重构用的都是外部配置好的现成模型，行为完全由 prompt 文本和采样参数（本臂统一温度 0）决定。这不是某一个阶段的局部差异，而是决定了整个系统"能力从哪里来"的根本性质变化——论文与上游的能力来自训练，本臂的能力来自 prompt 工程对训练结果的模拟，后果之一就是差异 23 提到的中文语料语言不稳定问题：论文靠训练把输出语言锁定成英文，本臂没有对应的训练约束。

## 附：推导

1. 差异 11、15、21、25 不是四条孤立观察，而是同一个根因的四个侧面。根因是本仓库臂完全不训练（差异 25），这直接决定了它必须用固定 prompt 和外部接管的方式去模拟论文里本该由 GRPO 学会的两件事——"何时检索"（差异 15 里的第三列）和"如何重构"（差异 21 里的第三列默认改宽）。而差异 11 揭示的是：即便在论文和上游这一侧，"重构能力是训练学来的"这件事本身在论文实际配置下也没有真正发生——所以本仓库臂"不训练"这个决策，某种意义上是在向论文实验的真实行为（重构未被训练）而非论文的文字描述（重构应被联合训练）靠拢。
2. 差异 7（embedding 换型号）与差异 10（剪枝默认关闭）看似互不相关，实际都源于同一类"本臂缺少上游可用信号"的约束：embedding 换型号是仓库级的统一口径选择，与本系统本身无关；但剪枝默认关闭是本系统特有的结构性限制——LoCoMo forced-call 下没有 episode 成功这个信号，效用分的成功计数分量永远是常数，如果开启剪枝，会把所有被检索用满 3 次的记忆当作"低效"误删，不管它实际是否有用。
3. 差异 13（标签词序）与差异 18（格式奖励构成）都只发生在 Paper↔Code 之间，与本仓库臂无关——因为这两处差异的载体（策略自己输出的协议标签、GRPO 训练时的格式奖励函数）在本臂里根本不存在：本臂不需要策略输出任何协议标签（检索由 harness 直接触发），也没有任何奖励函数在训练时被计算。这类"训练框架内部的机制性差异"天然不会传导到一个不训练的复现臂上。
