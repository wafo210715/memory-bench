## 重点差异详述

### 1. 多跳检索控制器：从默认能力掉到外挂且默认关（B8，能力损失）

论文把「迭代到证据足够或触顶上界」写成检索模块的默认设计，主文、附录算法、伪代码、消融四处互证（txt:755-757、2520-2542、2674-2702、3878-3879）。代码本体完全没有：主检索流程无循环、无跳数参数，`plugmem/` 包 grep `multi_hop|Tmax|max_hop|enough` 零命中。唯一实现在 HotpotQA 评测脚本里（`eval_qa_all.py:122-221`），只对语义模式生效，且轮数参数默认 1 即默认不走（`:242`+`:480`）。后果有两个：默认跑法下三个基准都没有多跳，论文 F.2 的增益数字与默认配置脱节；即便打开开关，脚本那套（各轮取并集、无新增即停、纯拼接）也不是论文的算法（`:216-219`、`:183-185`、`:213`）。

### 2. 处方质量分：评委是默认死（A2，能力损失）

论文明确写了第三位独立 LLM 评委，给每条处方打 1–10 分，prompt 独立成 Listing，与程序知识抽取分列（txt:728-730、2426-2427；Listing 3 @2236 vs Listing 6 @2437）。代码里函数定义在但零调用，所有处方的分恒为 0.0（`inference/structuring.py:96,124`）；`src/` 版更直白，调用那行整个被注释掉、下一行写死 0.0（`structuring_inference.py:138-139`）。这是「文档承诺了已被摘掉的能力」。它还是重排退化的上游：质量分恒 0，按质量复用处方的设计就没有信号可用（清单 #6 依赖本条）。

### 3. 推理压缩模块移出系统边界（B6，能力损失）

论文把 Reasoning Module 列为三大组件之一，去掉了准确率掉 2.7 个点、token 涨约 26 倍（txt:768；Table 6 txt:1294-1302）——它的本质是把多条记忆压成一段可执行指导的压缩器。代码里记忆系统只把结果套模板渲染成消息就返回（`memory_graph.py:1079-1092,1108`），压缩那次 LLM 由调用方各自解决，两个基准都直接用 gpt-4o（`eval_longmemeval_all.py:102`；`plugmem_agent.py:234`）；仓库留了收回边界的函数但三个评测脚本零调用（`retrieve_and_reason():1274-1297`）。能力没有从仓库里消失，但责任与成本都从记忆系统转移到了调用方——论文消融里那 26 倍 token，正是没有它时调用方要付的代价。

### 4. LME 复现配置与论文表头矛盾（B7，文档脱节）

论文 Table 3 表头：推理 Qwen2.5-72B、基座 Qwen2.5-72B（txt:1057-1058；E.1 txt:3310-3313）。复现脚本硬编码 gpt-4o 做压缩和最终回答（`eval_longmemeval_all.py:102,116`），且封装函数显式实参优先，环境变量改不动（`src/utils.py:142`）。也就是说 Table 3 的 75.1 无法用仓库当前脚本按论文配置复得。WebArena 无此问题：Table 5 表头 Q32+4o 与代码一致。这条不是新旧演进——脚本和论文摆在一起的当下就是矛盾的。

### 5. 意图去重：从语义判重换成字面匹配（A3，设计演进）

论文：新意图与已有意图算 embedding 余弦，超过阈值才让 LLM 合并改写并刷新向量（θ_equal 全文无取值，txt:2428-2431）。代码：字典查 key，只有字符串完全相同才触发合并（`memory_graph.py:515,519`；`insert()` 全程无余弦，`:363-593`）。机制换了，效果随之改变：措辞不同但语义相同的意图再也不会合并，程序子图随使用积累冗余意图节点；而检索侧程序模式又只取最好的 1 个意图（`:892`），冗余直接稀释命中质量。附带两处记录：合并串算了但没写回节点文本，文本与向量脱节（`:519-524,565,576,583`）；服务接口暴露的四个去重阈值写入路径从不读，是死旋钮（`routes/memories.py:136-143`）。

## 附：推导

1. 判「文档脱节」的分界线是论文有没有明确承诺：Get_Return 写死了独立评委和量程，判承诺违约（清单 #2）；重要性/新近度原文是 optionally，判留白未填、半建未完成，而非违约（清单 #6）。同一个 B4 格子，两种判词。
2. 因果链不是并列观察：#2 质量分恒 0 → #6 的可选质量信号物理缺席 → 按质量复用处方的整场戏不在；#1 的 B8 空 → 抽象查询由每跳一次降为每次检索一次 → 论文 stop-check 与改 query 的聚焦循环整体缺席。清单允许分行列，但依赖关系写在了「差异」列里。
3. 当前 HEAD 的复现脚本状态 ≠ 产出论文数字时的状态：两个基准已切到打向 `plugmem/` 服务的 HTTP 客户端（commit `95c2a8c`，2026-05-26），LME 脚本又硬编码 gpt-4o。Table 3 的 75.1 是论文实验期的产物，引用时带上这个定位，不要用当前 HEAD 去质疑或背书它。
